# AUTOBOT_* Environment Variables

> **Tracking:** [#16317](https://github.com/mrveiss/AutoBot-AI/issues/16317). The table below is generated
> from the registry, so don't edit it by hand.

Every `AUTOBOT_*` environment variable must be registered before code reads it. The pre-commit hook
`env-vars-documented` (`pipeline-scripts/check_env_var_registry.py`) enforces that, and it fails when the
table below no longer matches the registry. `code-quality.yml` runs the same check over the whole tree.

To add a variable:

1. Add a `register_env_var(EnvVarSpec(...))` call to your component's module,
   `autobot_shared/env_registry_<component>.py`. If the component has none, create one and import it from
   `autobot_shared/env_registry.py` alongside the other `env_registry_*` imports. `env_registry.py` itself
   is at its size ceiling.
2. Run `python3 pipeline-scripts/generate_env_docs.py` to regenerate the table.
3. Stage the registry module and this file.

The table has no count line, and its rows are sorted by name. So two PRs that each add a variable only
conflict when their rows sort next to each other.

## Env-file family

The tracked env files are templates. The installer and the Ansible roles write the real ones.
[#18555](https://github.com/mrveiss/AutoBot-AI/issues/18555) settled the shape of the family:

| File | Used by |
|---|---|
| `docker/.env.docker` | Docker Compose, through `--env-file docker/.env.docker`. This is the **only** Docker env file. |
| `.env.example` | The full annotated reference for a native install. |
| `.env.base` | The keys every native environment shares, written once. Always loaded first. |
| `.env.localhost`, `.env.native-vm`, `.env.network`, `.env.network-template` | Per-environment overlays on `.env.base`: each holds only what differs. Load the base, then one overlay (`cat .env.base .env.localhost > .env`, or `source` both in that order). |

Host keys use one format in every file:

- A `*_HOST` key is a bare host name or IP address, with no scheme, port or path. Ports go in the matching
  `*_PORT` key. Compose builds `http://${AUTOBOT_OLLAMA_HOST}:11434`, so a URL in a host key breaks it.
- A `*_URL` or `*_ENDPOINT` key carries the scheme, as in `http://`, `redis://` or `ws://`.
- `OLLAMA_HOST` is Ollama's own variable. Its upstream format is `host[:port]`, and it is the only exception.

`repo_tests/env_file_family_18555_test.py` enforces both rules over every tracked env file. It fails when
a host key breaks the format, when two files disagree on a key's format, when a second Docker env file
appears, when an overlay repeats a `.env.base` key with the same value, or when a root `.env.<env>` file
appears outside the known overlays.

| `AUTOBOT_WORK_CLAIM_TTL_S` | orchestration | int | `300` | How long an agent's work claim survives without a renew (#15947). This is a coordination policy, not a tuning knob: the value is how long a crashed agent's scope stays blocked to every other agent, so the floor stops a claim expiring mid-write and the ceiling bounds a stale hold at one hour. A running task renews for its own lifetime, so raising this does not make long tasks safer -- it only makes a dead holder's scope take longer to free. Range: 10–3600. |
| `AUTOBOT_WORK_CLAIM_WAIT_TTL_S` | orchestration | int | `900` | How long an agent keeps its place in a work-claim queue without renewing (#15948). Deliberately longer than AUTOBOT_WORK_CLAIM_TTL_S: a waiter that expired before the holder it is queued behind would never be promoted, and would look to an operator like a queue that silently drops people. The ceiling bounds how long a dead waiter occupies a position before it is pruned on the next read. Range: 30–7200. |
| `AUTOBOT_WORK_CLAIM_YIELD_TIMEOUT_S` | orchestration | int | `30` | How long a requester waits for a claim holder to answer a yield request before treating the silence as a refusal (#15948). Short on purpose: the requester is blocked while it waits, and a holder that has not answered in this long is busy working, which is itself the answer. Raising it does not make a yield more likely, it only makes the requester wait longer to be told no. Range: 1–600. |
