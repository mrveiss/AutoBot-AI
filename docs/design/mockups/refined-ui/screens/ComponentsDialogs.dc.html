Dialog vs drawer vs inline

Use for: choosing the container before choosing the dialog type
ContainerChoose whenAvoid whenExample
Modal dialogA short task or decision must finish before continuing; context behind does not need to be read.The user must compare with the page, or the task has more than ~6 fields.Approve agent command, delete company
Side sheet (drawer)Inspecting or lightly editing one item from a list while keeping the list visible.The action is destructive or blocking.Work item detail from Backlog
Inline / pageEditing is the main job, long forms, anything needing a URL or browser back.—Agent configuration, routine editor
Toast / bannerInformation that needs no decision.The user must acknowledge — use an alert dialog.“Agent deployed”

Rules: If a dialog needs its own scroll and tabs and steps, it is probably a page. Never open a dialog from a dialog; replace the content (wizard) or close first.

Behaviour rules for every dialog

Use for: implementation checklist
TopicRule
Focus trapTab / Shift+Tab cycle inside the dialog; page behind is inert. Side sheets are the exception (non-modal).
Initial focusFirst field for forms; search for pickers; Cancel for risky confirms; the only button for alerts; × for read-only views. Never the destructive button.
Esc / closeEsc = Cancel. Scrim click = Cancel unless input is dirty (then guard). Session-expired ignores both.
Return focusTo the element that opened the dialog; if it was removed (deleted row), to the next row or the list heading.
ARIArole="dialog" or "alertdialog", aria-modal="true", aria-labelledby → title, aria-describedby → description/consequence text.
ButtonsRight-aligned, Cancel then primary. Verbs, not OK/Yes. Destructive primary uses the danger style; in a 3-way guard the destructive option moves footer-left.
VisualsBorder separates the dialog from the --bg scrim; no shadows. Max height 85vh, body scrolls.
