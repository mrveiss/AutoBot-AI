Components · Tooltips

Short, non-interactive labels that name or explain a control. Every tooltip below is rendered open next to its trigger; the live row reacts to hover, focus and Esc.

Placements

Use for: choosing where the bubble sits; top is the default
top-start top · default top-end right bottom left
top — default for buttons, icons, pills.
top-start / top-end — wide triggers at a container edge (table cells, left/right toolbar ends); arrow sits 12px from the aligned edge.
right — collapsed sidebar icons; left — right-edge controls.
bottom — triggers in the top nav or near the viewport top.
Collision: flip to the opposite side first, then shift along the edge; keep 8px from the viewport. Never cover the trigger.

Rules: One tooltip open at a time in the product (this specimen shows six for reference). Offset is always 8px and the arrow points at the trigger's centre unless start/end aligned.

Do & don't

Use for: review checklist
Copy agent ID

Do Name icon-only controls with a short verb phrase.

Approve

Don't Repeat a visible label — it adds noise, not information.

Search knowledge /

Do Show on keyboard focus, not only on hover; Esc hides.

Paused by policy. Resume

Don't Put links or buttons inside — unreachable by keyboard; use a popover.

Requires admin role

Do Explain disabled actions via aria-disabled or a focusable wrapper.

Don't Hide errors or required info in a tooltip; write them inline.

Pin to sidebar

Do Keep it to one line (rich: title + 2 lines max, 280px).

<button title="Pin">

Don't Use the title attribute — no focus support, no styling, unreliable timing.

Run heartbeat now

Don't Cover the trigger or the content the user is reading; flip instead.

Rules: Before shipping: role="tooltip" + aria-describedby, focus and hover parity, Esc hides, never essential information, readable in all four themes.
