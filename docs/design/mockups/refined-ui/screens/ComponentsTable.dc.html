Rules

When to reach for a table, and how to keep it readable in all four themes.

Table vs. card grid

  • Table when people compare the same 4+ attributes across many records, sort, or act in bulk (work items, agent runs, secrets, members).
  • Card grid when records are few (under ~12), visual, or heterogeneous (agents, plugins, portfolios) and each card has its own primary action.
  • Never both for the same data on one screen; offer a view switch instead.

Alignment & type

  • Numbers (runs, cost, tokens, durations) right-aligned with tabular figures, header aligned the same way.
  • Mono for IDs, hashes, timestamps, durations and amounts; sans for titles and names.
  • Text left-aligned; truncate titles with ellipsis and full text on the detail view.
  • Status is a pill with words — never a colored dot alone.

Behaviour & a11y

  • Sortable headers are buttons inside the header cell; the cell carries aria-sort. One sort key at a time.
  • Select-all covers the current page and shows mixed when partial; offer “select all matching”.
  • Menus close on Esc and on selection; bulk results announce in an aria-live region with Undo.
  • Loading sets aria-busy; errors use role="alert" and keep filters intact.
