Pattern · Interface modes (Minimal / Full)

One switch that hides advanced features for people who only need chat, knowledge and approvals — without removing anything.
Preview mode
Preview theme
{{uiAnnounce}}

Purpose

Use for: reducing cognitive load for everyday users, without forking the product.
ProblemAutoBot exposes analytics, automation, SLM, MCP and developer tools on every screen. For a member who just chats and approves, that is noise.
SolutionFull is today's UI. Minimal hides items marked advanced, collapses technical output into plain-language summaries, and keeps one link back to everything.
ScopePresentation only. Permissions, routes and data are identical in both modes. Default is Full.

Mechanism · .adv and .only-min

Use for: every app file — identical so it can be rolled out by search-and-replace.
1 · Root + CSS (append to helmet style) 
<div class="th" data-theme="…" data-ui="…">

.th[data-ui="minimal"] .adv{display:none !important}
.th[data-ui="minimal"] .adv-only-full{display:none !important}
.th .only-min{display:none !important}
.th[data-ui="minimal"] .only-min{display:flex !important}
.th[data-ui="minimal"] .only-min.blk{display:block !important}
2 · Mark markup 
<a href="Analytics.dc.html" class="adv">Analytics</a>
<section class="card adv">Execution plan…</section>
<section class="card only-min">
  AutoBot checked 6 nodes · 1 needs a restart
</section>
<p class="sect adv">Research</p>  <!-- empty group -->
3 · Script (inside the same Component) 
data-props: "ui":{"editor":"enum",
  "options":["full","minimal"],"default":"full"}

componentDidMount: read 'autobot-ui-mode'
setUi(id): localStorage.setItem(…) ; setState({ui:id, uiAnnounce})
renderVals: ui = state.ui || props.ui || 'full'
  uiModes: [minimal, full] → label, cls, pressed, pick
  showAll: () => setUi('full')

Rules

Use for: deciding what may be marked .adv.
  • NeverHide approvals, errors, security notices or data the user owns (their chats, documents, budgets that block them). A failed status pill stays even when other status badges are hidden.
  • Hidden ≠ disabledMinimal only removes entry points. Direct links, bookmarks, search results and notifications still open the page; that page shows the “Show all features” link.
  • AlwaysKeep “Show all features” reachable in Minimal, and the mode toggle visible in the top nav in both modes.
  • Per userMode is stored per user per device. Administrators set the default and can lock it per role in SLM; a locked toggle is shown disabled with a reason.
  • AnnounceEvery change is announced via aria-live="polite": “Minimal interface on. Advanced features hidden.” Focus stays on the toggle.
  • Replace, don't dropWhen Minimal hides technical detail that carries meaning (execution plan, terminal output), show a one-line plain-language summary with .only-min.
  • FutureDon't hide items the user pinned or used in the last 14 days — they are promoted to essentials for that user.
