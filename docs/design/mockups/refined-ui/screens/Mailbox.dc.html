Pattern rules

Company OS mailbox (#13707)
Agents may read, search, label and summarise on their own (SAFE tier).
Anything outbound is a draft that needs approval, shown with its risk tier before send.
An agent draft is never styled like a sent message: dashed box, agent name, "Needs approval".
Remote HTML is sanitised; remote images are blocked until you load them.

Agent draft lifecycle
Needs approval→ Edited by you→ Approved · sent or Discarded Blocked · FORBIDDEN

Rules. Sync and offline banners name the cause, the last good sync and one recovery action. Skeletons set aria-busy and never last longer than the sync itself. Blocked drafts (credential disclosure, payment instructions) can't be approved from the mailbox at all.

Sign-off tiers for mail

Reuses CommandRisk, no new enum
TierMail actionDefault
SAFERead, search, classify, label, summariseAuto
MODERATEReply in an existing thread to a known correspondentAuto in full autonomy, ask in sign-off
HIGHNew external address; attachments outAlways ask
CRITICALBulk send; large or hidden recipient setPer-item sign-off
FORBIDDENPayment instructions, credential disclosureNever

Rules. The tier pill shows on every draft and in compose before send. "Remember this decision" uses ApprovalMemoryManager scoped to the mailbox, not a project path.
