Column width & truncation

Use for: deciding what shrinks when the table is narrower than its content.
IDWork itemNoteTokens
AL-142Publish security artifact packBundles SBOM, threat model and pen-test summary. Waiting on a data_access approval before publishing to Knowledge.48,210
AL-137Benchmark vector stores for KnowledgeComparing ChromaDB, Qdrant and pgvector on recall@10 and p95 latency with the ADR corpus.596,118
ID col = --tbl-min-col 96title: ellipsisnote: 2-line clampnumbers: never cut
  1. Never truncate IDs, numbers, money, dates or status words. Their column widens instead.
  2. Ellipsis one-line text past --tbl-cell-max 360 (or its fixed column); put the full value in title and keep it in the accessible name.
  3. Two-line clamp only for secondary description columns, and only in comfortable density; compact always single-line.
  4. Minimum every column at least --tbl-min-col 96; below that, hide the column via the column picker instead of squeezing it.
  5. Overflow wider tables scroll horizontally inside their card with the first ID column pinned; under 760px switch to the card-list fallback.

Rules: truncation is a last resort after hiding optional columns. Hover tooltips are not enough on their own: the row detail must show the full text.
