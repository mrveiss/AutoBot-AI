AutoBot Design System · Introduction

What the system is for, the principles behind it, every board in one place, and how to use it in the Vue app.

One calm, accessible system for every AutoBot screen

The AutoBot Design System is the shared language of the self-hosted AI platform: chat, knowledge, Company OS, analytics and the admin console. It defines the tokens, components and page patterns that keep agents, approvals and fleet data readable in four themes, from a bright office to a dark ops room or a screen reader.

Principles

Six rules every board and every Vue component follows.

Calm and corporate

Quiet navy and neutral surfaces, one accent, generous spacing. Data and decisions stand out; chrome stays out of the way.

Illustrated line icons

1.5px strokes in --stroke with flat token fills (i1 / i2 / i3) on a soft tile. No emoji, no photo icons, no brand logos inside UI.

No shadows

Layers separate with 1px borders (2px in High contrast) and surface steps bg → surface → surface2. No box-shadow, glow or gradient.

Token-only colour

Markup uses var(--token) and nothing else. A literal hex value in a component is a bug, because it breaks the other three themes.

Status never by colour alone

Every status carries a word, and high-priority ones add a glyph (✓ ! ✕). Charts use outlined marks, patterns and direct labels.

Accessible by default

AA contrast in Light, Dark and Monochrome; AAA (7:1) text in High contrast. Visible 3px focus ring, full keyboard paths, 44px touch targets.

How to use in the Vue app

The boards are the spec; the Vue 3 frontend consumes the same CSS.

1Import the shared stylesheet once

All four token blocks and every class on these boards (.card, .btn, .pill, .tile, .ic …) ship as one stylesheet. Import it in the app entry; components never redeclare tokens.

// src/main.ts
import '@autobot/design-system/autobot-ds.css'
createApp(App).use(router).mount('#app')

2Set [data-theme] on <html>

The theme is a single attribute on the document root: light, dark, contrast or mono. The .th scope on these boards maps to :root in the app.

<html lang="en" data-theme="dark">
/* autobot-ds.css */
:root, .th { --bg: #F5F6F8; … }
:root[data-theme="dark"] { --bg: #0E1420; … }

3Read the theme from profile settings

The user's choice lives in Preferences → Appearance and is stored on the profile, so it follows them across devices. Apply it before first paint; fall back to prefers-color-scheme only when unset.

// src/composables/useTheme.ts
const theme = computed(() => profile.value?.settings.theme ?? 'light')
watchEffect(() => {
  document.documentElement.dataset.theme = theme.value
})

4SLM console uses .th.slm

The SLM admin app mounts inside a wrapper with both classes. Only density and accent tokens change; the theme attribute on <html> still decides light, dark, contrast or mono.

<div id="slm" class="th slm">
  <RouterView />
</div>
.th.slm { --row-h: 32px; --accent: var(--info-fg); }

Rules: no scoped colours in .vue files: use var(--token) or an existing class. New visual needs start as a token or class in the shared stylesheet, shown on a board, then used in the app.

Contributing

How a change gets in.
  1. Check the boards first. Most needs are already a variant or state of an existing component.
  2. Propose on a board. Add the specimen with all states (default, hover, focus-visible, active, disabled, loading, error) and a Rules note.
  3. Verify in all four themes with the Preview switch, then keyboard-only and with a screen reader.
  4. Open a PR that changes the board and autobot-ds.css together; the reviewer approves both or neither.
  5. Log it in the changelog below with the date and the boards touched.

Versioning

Semantic versions for the stylesheet and boards.
  • Major (2.0) renames or removes a token or class, or changes a component's markup contract. Ships with a migration note.
  • Minor (1.1) adds a component, variant, token or board without breaking existing markup.
  • Patch (1.0.1) fixes contrast, spacing or a bug; no API change.
  • Deprecations stay for one minor release, marked "Deprecated" on the board with the replacement named.
  • The sidebar line "v1 · 4 themes" always shows the current major version.
