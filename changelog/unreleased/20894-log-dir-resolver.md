Logs are never written inside the source tree: one resolver (`AUTOBOT_LOGS_DIR`; its one declared default, `log_dir.LOGS_DIR_DEFAULT`, is unset in both env planes and resolves to the XDG state dir; a test run gets the root conftest's per-run temp dir) replaces the cwd-relative `logs` default. Log files and their directory are created at the first record (`FirstWriteFileHandler`), never at import, so importing a module writes nothing; an unwritable directory turns the file handler off with one stderr line instead of failing the import.

Containers: `docker-compose.yml` sets `AUTOBOT_LOGS_DIR=/app/logs` (the `backend_logs` volume) for backend, worker and celery-beat, as it already did for the SLM; the hardened overlay's home `/app` is read-only.

Deployment check: the backend unit loads `EnvironmentFile={{ backend_code_dir }}/.env` (`autobot-slm-backend/ansible/roles/backend/templates/autobot-backend.service.j2:62`), written from `backend.env.j2`; `distributed.env.j2:35` is loaded only by the coordinator unit (`autobot-coordinator.service.j2:14`), so the backend did NOT get `AUTOBOT_LOGS_DIR`. Now set at `backend.env.j2:68` from `backend_app_log_dir` (`roles/backend/defaults/main.yml`, `<base>/logs`, the application's own rotating handlers). It deliberately differs from `backend_log_dir` (`/var/log/autobot`), where the units' `StandardOutput=`/`StandardError=` append the same file names: one file written by both would carry duplicate records and be orphaned by the application's rotation. The audit log default is unchanged at `<base>/logs/audit.log`. The plugin logger now reads the same resolver.

Every Python service unit now sets `AUTOBOT_LOGS_DIR`, to a directory different from the one its `StandardOutput=` appends to (both guarded by `repo_tests/service_units_set_logs_dir_20894_test.py`): backend, celery, celery-beat and mcp-bridge via `roles/backend/templates/backend.env.j2:68` (`backend_app_log_dir`); slm-backend via `roles/slm_manager/templates/autobot-slm-backend.service.j2` (`slm_app_log_dir`, `<slm_backend_dir>/logs`); npu-worker, tts-worker and ai-stack via their `*.env.j2` (`npu_app_log_dir`, `tts_app_log_dir`, `ai_app_log_dir`, each `<install_dir>/logs`, created by the role beside the install directory); already set: coordinator (`distributed.env.j2:35`), agent (`agent.env.j2:7`), slm-agent (`slm-agent.service.j2:73`). The four static units under `autobot-infrastructure/*/templates/` set it to `<WorkingDirectory>/logs`, what the cwd-relative default resolved to, and grant it as an optional `ReadWritePaths=-` entry so a missing directory never stops the unit starting. Where a role's application directory differs from the old working-directory `logs/`, those logs move on the next deploy.
