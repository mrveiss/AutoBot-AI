# Ansible <-> requirements version divergence baseline (#15568)
#
# One `<path-from-repo-root>::<pep503-package-name>` per line. Each entry is a
# package that an ansible pip declaration site versions differently from every
# `requirements*.txt` declaration of the same package.
#
# `repo_tests/ansible_requirements_parity_test.py` enforces two things:
#
#   1. any divergence NOT listed here fails — a new restatement, or a bump that
#      moved one manifest and not the other, which is the failure #15408 hit
#      seven times over on `openvino`;
#   2. any entry listed here that no longer diverges — because it was fixed, or
#      because the declaration was removed — ALSO fails. A stale entry exempts
#      nothing while looking authoritative.
#
# THIS LIST ONLY SHRINKS. Seeded from the audit #15568 asked for, run
# 2026-09-04 over 21 ansible pip declaration sites and 34 requirements files.
# Nothing may be added to it to make a red go away: a new divergence is either
# fixed at the declaration, or the package moves onto `constraints/shared.txt`.
#
# Two divergences found by that audit are absent because they were fixed in the
# same change: `numpy` in `group_vars/aiml.yml` and in `roles/tts-worker`, both
# now bare names against `constraints/shared.txt`. Packages the constraints file
# guards are never eligible for this baseline — a separate assertion in the same
# test fails them outright.
#
# The remaining 55 fall into three classes, one issue each. Every line below is
# a live finding with an owner, not an accepted state.
