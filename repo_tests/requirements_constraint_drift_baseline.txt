# requirements constraint-drift baseline (#17448)
#
# One `<service requirements file>::<package>` per line. Each entry is a package
# declared on BOTH planes whose two constraints can resolve to DIFFERENT
# releases -- typically `==X` in requirements-ci/*.txt against an unbounded
# `>=X` in the service file, so CI installs exactly X while the service takes
# whatever published most recently.
#
# WHY THIS IS NOT COSMETIC. That is how the SLM test venv took SQLAlchemy 2.1.0
# while CI's own venv stayed on 2.0.54. 2.1 dropped `greenlet` as a hard
# dependency, nothing in the tree declared it directly, and every SLM test
# module failed at import (#17433). The two migration gates reached the same
# 2.1.0 from the same cause a day later (#17499). Two point fixes; the
# mechanism was untouched both times, and these are the remaining candidates.
#
# #14551's guard, directly above this one in the same module, checks only
# whether a package is MIRRORED into CI at all -- it states in its own docstring
# that it does not merge the two dependency sets. A pair listed here passes that
# check and still installs two different releases.
#
# THIS LIST ONLY SHRINKS. An entry leaves when the two constraints are made to
# agree. A pair that stops diverging while its line remains is a hard error, not
# a silent no-op: a stale entry exempts nothing while looking authoritative.
#
# Measured 2026-09-25: 78 pairs appear on both planes, 52 of them can diverge.
# Adding a line here is a decision to leave one of those 52 in place, and it
# needs a reason in the PR that adds it.
